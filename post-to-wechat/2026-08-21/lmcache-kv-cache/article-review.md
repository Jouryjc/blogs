# 《Agent 上下文越跑越贵，先把 KV Cache 从推理进程里拆出来》审稿报告

## 结论

初稿定位准确，开头有 Agent 多轮执行场景，也给出了明确的采用边界。机械指标为 1726 个中文字符、6 个二级标题、3 张正文图、2 个 CTA 信号；`ai_smell_hits` 与 `warnings` 都为空。

文章可以进入优化，但不建议直接发布。当前主要问题不是“AI 味”，而是两处工程判断还可以更扎实：读者容易把 KV Cache 命中理解成省掉全部输入费用，也容易把 LMCache 理解成独立缓存服务上线后自然提速。

## 必改项

1. 在 KV Cache 解释后补一段“命中不等于免费”：缓存读取、跨 PCIe/网络搬运、序列化也会耗时，比较对象应是读取旧 KV 与重新 prefill。
2. 把 Prefix Cache 失效规则写得更精确：增长发生在稳定前缀之后仍能复用；真正麻烦的是前缀内容或顺序变化，以及多个独立片段的组合。
3. 补 LMCache 的数据路径和故障边界：推理进程请求 KV，缓存层命中后传回，未命中或超时应退回正常 prefill。
4. 保留 MI300X 的正反两组结果。低负载反例比单独展示 3 倍提速更能帮助读者做决定。
5. 给检查单加一个最小测试方法：同一批真实请求回放三次，只切换缓存策略，记录模型、硬件、并发、上下文与命中 token。

## 去 AI 味检查

- 未命中“换句话说、这意味着、真正、核心、本质、总的来说”等高风险模板词。
- 第一屏从 Agent 第 20 轮的具体动作切入，没有百科式定义开场。
- 关键判断都跟着条件或反例，没有把项目方基准写成通用结论。
- 结尾落到六项指标与真实流量回放，不用“希望对你有帮助”收尾。

保留的营销风险只在标题里的“先把……拆出来”。这是有意保留的点击张力，正文第五段立即限定为“长输入、高复用、高并发、显存吃紧”同时出现，风险可控。
