这个插件页讲的是一个很实用的流程：

**先读项目，再推荐配置。**

它会根据仓库结构、依赖和代码模式，给出更贴近当前项目的自动化建议。

我会把它拆成 4 个动作：

1. 先看项目类型。
2. 再看依赖和目录。
3. 找出最适合自动化的环节。
4. 只先落地最值得配的 1-2 个建议。

小余判断：这类工具适合新项目接手、老项目补工程化配置、团队统一工作流。不要上来追求全套，先从当前仓库最痛的环节开始。
