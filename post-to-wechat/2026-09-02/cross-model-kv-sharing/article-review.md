# 《模型切换别再重算长上下文：KV Cache 开始跨模型接力》审稿报告

## 总评

这是一篇定位清楚的“5 分钟蒸馏”论文解读。文章没有把跨模型 KV sharing 写成已经成熟的万能层，而是把读者最容易被漂亮数字带偏的地方拆开：源 KV 是否本来就存在、延迟到底测了哪一段、质量是否稳定、translator 是否能跨任意模型对。

初稿已经没有脚本可识别的 AI 模板词。发布前人工审稿仍处理了五类高风险：第一屏缺少 trace 现场感；作者判断出现偏晚；长上下文分桶容易被写成因果；`899ms → 138ms` 的前提与数字相隔过远；结尾有趋势升华但缺少直接可执行的成本字段。

优化稿把增量成本限定语移到数字首次出现的位置，并把工程判断前移为两笔账、五道闸门和三列成本表。它现在适合发布，但结论只对 arXiv v1 的三个模型迁移方向负责。

## 具体 AI 味位置

自动脚本的 `ai_smell_hits` 为 0，人工审稿仍修改了三类总结器表达：

1. 开头从“一个 Agent 先……”改成多模型 trace，直接呈现 32K 上下文被读三遍。
2. “这同时带来一个工程判断”改为“我会先算两笔账”，把抽象总结变成部署动作。
3. 结尾的“方向很重要、把问题向前推一步”改成重画成本表，并明确新增源 KV 命中率、迁移端到端耗时、质量回退率三列。

## 优先修改

1. **限定 138ms。** 在数字首次出现时写清“源 Llama KV 已存在、只统计 Handoff 增量成本”，防止截图传播后变成端到端加速结论。
2. **收紧质量因果。** 8K–16K 与 16K–32K 是不同样本桶，只能当作长度风险信号，不能单独证明长度导致准确率下降。
3. **收紧跨家族质量。** 不写“整体不掉质量”，改为多个 Decode horizon 接近原生、但 H=16 和 H=512 更差。
4. **标记实现缺口。** 截至 arXiv v1，论文没有披露 transport module 结构、训练配方、硬件、并发、命中率或代码链接。
5. **交付决策对象。** 用五道工程闸门替代论文结论复述，要求同时核算成本、质量和 fallback。

## 事实口径

- Qwen2.5-7B → 1.5B 的 LongBench2 准确率为 27.59% → 34.48%，基于 116 个计分样本；7B 原生为 45.69%。
- Qwen2.5-1.5B → Gemma-2-2B 在 4K 的正文表格值是 67.04%；摘要写 67.05%，按原始耗时计算应四舍五入为 67.04%。
- Llama3.1-70B → Qwen2.5-7B 的 899ms → 138ms 是已有源 KV 后的增量 Handoff 比较；准确率同时从 45.7% 变为 44.0%。
- `Universal` 被限定为通用系统抽象。论文只验证三个有方向的模型对，没有证明一个 translator 能接任意模型。
- 安全与多租户段落明确标为生产工程推导，不冒充论文已完成的评估。

## 剩余风险

- 文章只对 2026-09-02 获取的 arXiv v1 负责；代码链接和后续版本可能变化。
- 同家族 LongBench2 只有 116 个计分样本，延迟每个长度桶只有 3 个样本。
- Llama → Qwen 实验没有清楚披露数据集、样本数、上下文长度、硬件与重复次数。
