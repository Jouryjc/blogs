# 「要不要上异构图」决策清单 + PolyUQuest 论文精读笔记

> 蒸馏小余读者资料 · 后台回复「RAG」领取
> 配套文章：《RAG 一问官网就翻车？坑不在模型，而在网页被拍平成纯文本》
> 论文：PolyUQuest: Verifiable Structure-Aware Web RAG over Heterogeneous Graphs（arXiv:2607.08269）

## 一、要不要上异构图：决策清单

逐条打勾，✅ 越多越值得上；❌ 占多数就先别动手。

### 上异构图的信号

- [ ] 知识分布在几百到几千个互链页面上（大学 / 政府 / 医院 / 企业官网、内部 Wiki）
- [ ] 用户问题里有明显比例的跨页聚合题（"哪些 X 满足 Y"）
- [ ] 用户问题里有多跳实体题（"A 的 B 的 C 是什么"）
- [ ] 业务要求答案可溯源，"答对"不够，还要"指得出出处"
- [ ] 现有 GraphRAG 方案的 token 账单已经压不住
- [ ] 站点 HTML 结构规范、链接拓扑完整

### 先别上的信号

- [ ] 内容没结构：论坛帖、聊天记录、纯文档库（三层里两层不存在）
- [ ] HTML 质量差、链接稀疏的老站（图建出来是残缺的）
- [ ] 95% 以上的问题是单跳事实题（模式 B/C 用不上，白付建图成本）
- [ ] 没有人力维护域特定实体 schema（换域就要重新设计）

### 不建图也能马上做的一步

给每个文本块补两个元数据字段：**源页面 URL + 标题路径**（如"入学要求 > 研究生 > 非本地生"），引用时展示出来。不需要建图，一天改完，有据率和用户信任感立刻提升。

## 二、论文精读笔记

### 核心问题

现有 RAG 把网页当扁平文本，丢掉三层结构：

1. 超链接拓扑（页面之间）
2. DOM 层级 / 标题路径（页面内部）
3. 跨页实体（同一实体在多页反复出现）

### 异构图设计（离线）

- 节点四类：网页 𝒱_P、证据块 𝒱_B、实体 𝒱_E、话题 𝒱_T
- 边四类：页面—页面（超链接）、页面—块（包含）、块—实体（提及）、实体—实体/话题（语义关联）
- 块属性：源页面、标题路径、嵌入向量、长度、提及实体集
- 省钱关键：超链接和 DOM 是 HTML 现成结构，解析即得；LLM 只花在实体关系层

### 查询路由（在线）

- 第一层：轻量规则接明确结构信号（免 LLM）
- 第二层：LLM 分类器接长尾，输出三模式置信度

### 三种检索模式

| 模式 | 名称 | 场景 | 机制 |
|------|------|------|------|
| A | Direct Block Retrieval | 单跳事实 | 密集向量 + BM25 → 交叉编码器重排 |
| B | Navigation Retrieval | 跨页聚合 | 查询分解 → 页面检索 → 沿链接扩展邻近页 → 全局重排 |
| C | Entity Reasoning | 多跳推理 | 抽实体 → 沿关系边扩展 → 回溯源块综合评分 |

### 可验证引用

每个引用块携带：源页面 + 标题路径（可点回原文）+ 实体链接；Graph 视图可展开支撑答案的节点。

### 关键数字（港理工官网，4,240 页 / 300 问）

| 系统 | 正确性 | 覆盖率 | 有据率 | 查询 token | 建图 token |
|-----|------|------|------|-----------|-----------|
| ChunkRAG | 0.532 | 0.479 | 0.710 | 2,947 | — |
| HtmlRAG | 0.453 | 0.448 | 0.804 | 4,009 | — |
| FastGraphRAG | 0.295 | 0.469 | 0.737 | 4,484 | 28.1M |
| LightRAG | 0.610 | 0.612 | 0.559 | 29,825 | 37.4M |
| **PolyUQuest** | **0.644** | **0.649** | **0.921** | **2,968** | **17.5M** |

消融：去掉 DOM 块层级 → 正确性 -8.1 / 覆盖率 -13.9；去掉跨页导航 → 正确性 -2.0 / 覆盖率 -1.6。

### 局限（照搬前必读）

- 只在港理工一个站点评估，泛化未验证
- 迁移新域需重新爬取 + 重新设计实体 schema
- 依赖 HTML 质量和链接拓扑完整性
- 实体抽取消歧质量直接影响模式 C
