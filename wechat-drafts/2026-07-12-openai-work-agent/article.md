7 月 9 日，OpenAI 开了一场发布会，一口气做了三件事：把 Codex 并入 ChatGPT 桌面端（macOS 和 Windows）、推出面向办公场景的 ChatGPT Work agent、GPT-5.6 全线上线。

三件事背后是同一个数据：6 月初 OpenAI 公布，Codex 周活用户已经超过 500 万，其中约 20%——也就是 100 万上下——是不写代码的知识工作者。他们拿这个"编码代理"写报告、做表格、拼演示文稿、整理合同。

结论可以先给：编码代理正式办公化了。Codex 不再作为一个程序员专属工具存在，而是变成每个 ChatGPT 用户桌面里的执行引擎。这场发布会名义上是"ChatGPT 的下一章"，实际上是 OpenAI 对 agent 战场的一次改判——竞争的胜负手，从"谁的模型更会写代码"，换成了"谁能把用户的活干完"。

这篇文章把发布会的产品动作、Codex changelog 里的工程细节、以及 Anthropic 同一周的对照动作放在一起讲清楚。

## 一个编码工具，为什么五分之一用户不写代码

先看数据本身。500 万周活对一个开发者工具来说已经是夸张的量级，但更值得注意的是用户构成：约 20% 是知识工作者，不是开发者。

OpenAI 对这批用户的描述很具体：他们主要用 Codex 创建报告、电子表格、演示文稿、合同和其他工作产品，并且越来越多地用它做研究、数据分析、工作流自动化，甚至搭建轻量级小工具。

这不难理解。Codex 和聊天机器人的差别在于执行方式：它不是回答问题，而是接下任务、拆解步骤、操作文件和软件、最后交付一个结果。这套能力对"写代码"和"整理季度报告"是通用的——两者都需要读输入、按流程加工、产出可交付的文件。一旦非开发者发现这一点，编码代理就自然溢出了编码场景。

问题是，"Codex"这个名字和独立应用的形态，天然把非开发者挡在门外。OpenAI 的解法直接：把它并进所有人都在用的 ChatGPT。现有 Codex 用户的项目、设置和工作流全部保留，同时桌面端新增了 Markdown 文档编辑、GitHub PR 审查、跨仓库项目这些能力。对程序员来说 Codex 还在，只是换了个入口；对更广大的 ChatGPT 用户来说，一个会干活的代理凭空出现在了桌面上。

![Codex 从独立编码代理并入 ChatGPT 桌面端的整合路径：左侧是独立 Codex（周活 500 万、约 20% 非开发者），右侧是 ChatGPT 桌面端统一入口，同场发布 Work agent 与 GPT-5.6 三档模型，指向"编码代理办公化"](imgs/01-openai-work-agent.png)

同场发布的 ChatGPT Work agent 承接的就是这批溢出需求。OpenAI 把它描述为"为最有野心的工作打造的 ChatGPT"，覆盖网页、移动、桌面三端——定位不是聊天助手，而是一个替你把办公任务跑完的代理。

## GPT-5.6 押注的不是更聪明，而是更快的 Computer Use

这次 GPT-5.6 的发布方式值得单独说。它不是一个模型，而是三个：旗舰的 Sol、日常均衡的 Terra、快速便宜的 Luna。OpenAI 解释了命名规则：数字标识模型代际，Sol、Terra、Luna 标识可以独立演进的能力层级。API 定价分别是每百万 token 输入/输出 $5/$30、$2.5/$15、$1/$6，梯度拉得很开。

分层定价对 agent 场景是刚需。一个跑几十分钟的 agent 任务里，大部分步骤是搬运和执行，少部分步骤需要强推理——全程用旗舰模型是在烧钱。三档模型加上可调的难度设置（免费和 Go 用户用 Terra，Pro 和 Enterprise 可以在三档之间自由选择），本质上是把"按步骤分配算力"的选择权交给了用户。

而 changelog 里那句不起眼的更新，可能比模型本身更重要："Made Computer Use faster with GPT-5.6"——用 GPT-5.6 让 Computer Use 变快了。

Computer Use 是 agent 直接操作真实软件的能力：看屏幕、点按钮、填表单。它一直有两个硬伤，慢和贵——每一步操作都要模型看一次界面、想一次、动一次手。速度提升意味着这条成本与延迟线被压低，agent 操作 Excel、浏览器、内部系统的可行性边界随之外扩。ChatGPT Work 里还给 Pro 和 Enterprise 用户配了"ultra"加速模式，进一步印证 OpenAI 在把"操作真实软件"当作办公代理的主战场投入。

顺带一提：GPT-5.4 将于 7 月 23 日停用，还挂在旧模型上的集成需要尽快迁移。

## 工程侧更新：OpenAI 在给多智能体装刹车

发布会讲产品故事，changelog 讲工程实话。把 6 月下旬到 7 月 9 日三周的 Codex 更新连起来看，OpenAI 在密集补一类东西：多智能体的控制面。

| 能力 | 版本 / 时间 | 干什么用 |
|---|---|---|
| 多智能体委派三档控制 | v0.142.0（6/22） | 委派可配置为禁用 / 仅显式请求 / 主动，粒度到 thread 和 turn 级 |
| rollout token 预算 | v0.142.0（6/22） | 跨 agent 线程追踪用量，剩余预算提醒，耗尽时中止本轮 |
| DigitalOcean 远程工作区插件 | v0.142.2（6/25） | Codex 自己开 Droplet、配 SSH、接入为远程工作区 |
| 插件浏览器改进 | v0.142.0 起持续 | /plugins 按 OpenAI Curated / Workspace / Shared with me 分区；7/8 起远程插件默认启用 |
| AGENTS.md / skills 授权委派 | v0.143.0（7/8） | 项目配置文件和技能可以声明谁有权委派 |
| Ultra 高并发用量警告 | v0.144.0（7/9） | 选 Ultra 推理时，多智能体高并发会触发成本提醒 |
| usage-limit reset credits | v0.144.0（7/9） | 重置额度显示类型和过期时间，可选择兑换哪一笔 |

这张表读下来是一个清楚的信号：多智能体不再是演示片里的炫技，而是要进生产环境了，所以刹车比油门先行。

委派三档控制解决"子代理能不能自己再派活"的问题。proactive 模式下代理可以主动分身干活，explicit-request-only 要求用户点头，disabled 直接关死——并且可以在每个 thread、每个 turn 上单独设置。配合 7/8 上线的 AGENTS.md 和 skills 授权机制，委派权限第一次变成了可以写进项目配置的东西。

rollout token 预算解决"一次任务花多少钱"的问题。它跨所有 agent 线程统一记账，快用完时提醒，用完直接中止本轮。任何跑过多智能体任务的人都懂这个痛：子代理一层层派下去，token 消耗是乘法不是加法。预算机制等于给整棵委派树装了一个总电闸。

![多智能体的两道闸门：委派三档控制（禁用 / 仅显式请求 / 主动，可在 thread 和 turn 级单独设置）管"谁能派活"，rollout token 预算（追踪用量 → 剩余提醒 → 耗尽中止）管"最多花多少"，共同罩住一棵不断分叉的子代理树](imgs/02-openai-work-agent.png)

DigitalOcean 插件则把执行环境的边界推到了云上：Codex 可以自己开一台 Droplet、配好 SSH、当作远程工作区接入。加上默认启用的远程插件和分区清晰的插件目录，Codex 的形态越来越像一个可扩展的执行平台，而不是一个 CLI 工具。

## Anthropic 在同一周给出了同一个答案

把镜头拉远，7 月第二周其实是双巨头的同题作文。

发布会前两天，7 月 7 日，Anthropic 把 Claude Cowork 推上了网页端和移动端（Max 订阅用户），主打跨设备接力：在电脑上启动任务，手机上看进度，回来取结果。更有说服力的是随之公布的数据——Anthropic 采样了来自 60 万+ 组织的 120 万条匿名会话，业务流程运营占 33.4%，内容创作占 16.4%，而软件开发只占 8.7%。

一边是 OpenAI 的编码工具被 100 万非程序员征用，另一边是 Anthropic 的 agent 用量里 coding 不到一成。两家看着各自的数据，做出了同一个判断：agent 的主流需求不在写代码，在办公。于是同一周里，一家把编码代理并进大众入口，一家把办公代理铺满所有设备。

这不是巧合，是行业共识的形成时刻。

## Agent 的下一场竞争：谁能把活干完

对工程师，我的建议分三层。

**用工具的人**：别再把 Codex/Cowork 这类产品当"AI 编程工具"评估，评估维度应该换成任务交付——它能不能接一个模糊的活、自己拆解、自己找工具、最后给你一个能直接用的结果。你的非技术同事很快也会用上同款代理，提前搞清楚边界的人有信息差优势。

**做 agent 工程的人**：OpenAI 这三周的 changelog 就是一份免费的架构参考答案。委派权限进配置文件、token 预算带提醒和熔断、高并发触发成本警告——如果你在自建多智能体系统，这几件事迟早要做，不如现在就抄。

**观察行业的人**：记住 8.7% 和 20% 这两个数。前者说明 agent 用量的大盘在办公不在编码，后者说明编码代理的能力可以无缝溢出到办公。模型能力的故事讲了三年，接下来两个季度的故事是分发和控制面。

编码只是 agent 学会干活的第一课，办公才是正式上岗。竞争已经从"谁会写代码"变成"谁能把活干完"——而能把活干完的前提，恰恰是这些不性感的工程细节：委派要能管住，预算要能熔断，额度要能看清。
